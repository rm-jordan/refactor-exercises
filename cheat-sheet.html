Refactoring cheat sheet

If you see this → do this. Keep tests green. Small steps.

You see Do this
any on a parameter Type fields actually used (email?, amount, JSDoc in JS)
Long function (math + I/O) Extract pure logic; orchestrator: validate → work → log → return
Duplicate logic in 2+ functions One helper; thin exports if API must stay
if/else if on fixed strings Object lookup: MAP[key] ?? default
Magic numbers (18, 0.15, 5) Named const at top
Nested if pyramid Guard clauses → early return false
Same 4+ parameters everywhere One object type; bundle at boundary if tests use separate args
DB + email + analytics in one function Split steps; same order of side effects
null / missing fields Widen type; guard before . access
Many boolean flags (isUrgent…) Options object; map flags at top of function
.then async chain async/await; extract URL + error helper
Mutates input argument const copy = { ...input }; change copy only
Duplicated validation rules Call existing validators; don’t copy checks

First 5 minutes

  • Run tests
  • Say behavior out loud
  • List 2–3 smells
  • Ask: exports? TS or JS? tests fixed?
  • One refactor → tests again

Do not

  • Big-bang rewrite
  • Silent behavior changes
  • Frameworks / over-abstraction
